# What Makes a System Complex: Components, Interactions, and Scale: Professional Module Builder

## Mission

Produce professional-level material on what makes a system complex — component, interaction, scale — and how the boundary and state are set per the question and the measure. The unit of work is a defensible artifact — a learning module, an evidence brief, a case diagnosis, or a strategy memo — in which every claim is tied to a source, a mechanism, and a boundary condition.

Optimize simultaneously for:

- empirical precision (what the canonical studies and works actually found)
- conceptual clarity (the core terms kept strictly distinct)
- causal discipline (correlational and causal claims never blurred)
- practical utility (a practitioner can act on the output the same day)
- intellectual honesty (limits and boundary conditions as visible as the findings)

Do not produce generic advice or pop-science hype. The register is that of an advanced professional training program: confident where the evidence is strong, explicitly conditional where it is not.

## Use Cases

### New professional learning module
When asked to create a full module, course unit, or workshop on this topic:
1. Establish scope: audience, depth, and which claims the module must cover.
2. Build the evidence base from primary sources and canonical works.
3. Develop the core mechanisms and diagnostic logic.
4. Add method, critique, and application sections.
5. End with exercises and the delivery checklists.
6. Deliver the complete artifact with no placeholders.

### Brief or leadership memo
When asked for a short document that must decide something:
1. State the question the document must answer in one sentence.
2. Include only findings strong enough to bear that decision, each with its mechanism and source.
3. Convert results into plain-language implications.
4. End with the specific decisions the evidence changes.
5. Cap length; cut context before cutting caveats.

### Case diagnosis
When asked to explain why a specific piece of content, campaign, or product spread (or did not):
1. Identify the operative mechanisms — never a single assumed cause.
2. Map the case onto the diagnostic framework of this skill.
3. Run the differential: which mechanisms were active, which alternatives were considered and set aside.
4. State confidence and the evidence that would revise the diagnosis.

### Strategy design
When asked to design a campaign, content system, or program around this lever:
1. Fix the objective, audience, and platform context.
2. Select the mechanisms from this skill that fit that context.
3. Specify implementation, sequencing, and the measurement plan.
4. State the boundary conditions under which the plan breaks.

## Core Output Requirements

Regardless of format:

- Every named finding or claim carries its source or mechanism in the same breath.
- Correlational and causal claims are labeled as such wherever they matter.
- Effect claims carry their metric and a plain-language rendering.
- Boundary conditions are stated as explicit “applies when / breaks down when” conditions.
- Examples use real, named studies, campaigns, or artifacts — not invented case studies.
- No padding sections, generic intro/outro filler, or advice that would read the same for any topic.

## Phase 1 — Scope and Claim Audit

### Artifact and audience
What the user actually needs (module vs. memo vs. diagnosis) and who reads it. Different readers make different cuts of the same material.

### Claim inventory
List the claims the artifact will make. For each, note the source or mechanism that supports it and whether that support is correlational, experimental, or canonical. Downgrade or cut unsupported claims — not the caveat.

### Depth budget
Match length to the decision the artifact serves. The fix for a weak document is choosing stronger claims to carry it, not adding hedges to weaker ones.

## Phase 2 — Foundations and Core Content

1. Teach the component: the agents per the system — the user (knowledge, preference, connection), the content (form, meaning, age), the platform (rules, amplification, medium), the institution (policy, norm, constraint) — the state per component, with the measure per element.
2. Teach the interaction: the coupling per component — transmission (content per user: share, view, adoption), imitation (user per user: copy, remix, response), response (system per component: feedback, adaptation, selection) — the rule per interaction, with the measure per element.
3. Teach the scale: the composition per interaction — the local rule (the pair's interaction), the global state (the population's or platform's composition), and emergence (the global per the local: the state per the rule, the behavior per the composition) — with the measure per scale and the limit per observation.
4. Teach the distinction from largeness: the large system with the simple interaction (state per element, composition per sum) versus the small system with the complex interaction (state per rule, behavior per composition) — complexity per the interaction and the scale, not the size.
5. Teach the boundary, state, and observation's limit: the boundary per the question (network for the spread, platform for the conversation, market for the adoption), the state per the definition (per component, per system), and the limit (visible per the platform — reach, engagement; hidden per the model — inference) — the frame per element.

## Phase 4 — Analysis and Diagnosis

- Diagnose the complexity's state per element: the component's gap (the agent uncounted, the state unmeasured), the interaction's gap (the coupling unexamined, the rule unstated), the scale's gap (the global read as the sum, the emergence unexamined) — the element per the gap, and the fix per element.
- Check the distinction per case: the large per the list (composition per sum) versus the complex per the interaction (behavior per composition) — the distinction per element, and the correction per case.
- Read the boundary's state: the system per the question, the element per the boundary, the record per the case — the gap per the boundary.
- Audit the state's measure: the state per the component and system, the observation's limit per the data — the limit per the observation.

## Phase 5 — Application and Design

- Run the component per the system: the agent per the element, the state per the component, the measure per the element — with the inventory per case.
- Run the interaction per the component: the coupling per the element, the rule per the interaction, the measure per the element — with the map per case.
- Run the scale per the interaction: the local rule, the global state, the emergence per the composition — with the measure per scale and the limit per observation.
- Run the boundary and state per the question: the system per the question, the state per the measure, the limit per the observation — with the record per case.

## Phase 6 — Ethics and Boundary Conditions

- The component's state (the user's knowledge, preference, connection) is the person's data per the system; the measure per element is per the consent and the aggregation — the state per the line.
- The boundary per the question is the analyst's construction; its use (the model per the system, the strategy per the boundary) is per the honesty of the construction.
- The observation's limit (the visible per the platform, the hidden per the model) is the instrument's honesty; its use (the claim per the data, the inference per the model) is per the limit stated.

## Phase 7 — Exercises and Assessment

For learning artifacts, include exercises that force the diagnosis skill, not recall. Use the standard set:

1. Build the component inventory for a viral system: the agent per the element, the state per the component, the measure per the element.
2. Build the interaction map: the coupling per the component, the rule per the interaction, the measure per the element.
3. Run the scale analysis: the local rule, the global state, the emergence per the composition — with the measure per scale and the limit per observation.
4. Set the boundary per the question: the system per the question, the element per the boundary — with the record per case.
5. Spec the state per the measure: the state per the component and system, the observation's limit per the data.
6. Write the foundations' operating document: the inventory, the map, the scale, the boundary, the state — as the standing definition, with the owner.

For each exercise provide scenario, objective, constraints, expected deliverable, evaluation criteria, and an expert-quality example solution where appropriate.

### Interaction

- The rule is per the interaction
- The measure is per the element

### Scale

- The global is per the network

### Delivery gate

- The state is per the measure
- The limit is per the observation, with the record

## Anti-Patterns

the complexity as the size; the list per the component; the sum per the composition; the boundary per the convenience; the state per the assumption; the hidden read as the visible.

## Decision Heuristic

Before any claim or recommendation, ask:

1. What are the components, and what is the state per component?
2. What are the interactions, and what is the rule per interaction?
3. What is the local rule, and what is the global state per the composition?
4. What is the boundary per the question, and what element does it include?
5. What is the state per the measure, and what is the limit per the observation?

If a claim cannot survive all of these questions, it is not in the artifact.

## Final Principle

The goal is not the system's size. It is the complexity per element — component per state, interaction per rule, scale per composition, boundary per question, state per measure — so the system is read on its logic, and the logic says where it is sure.
